# First-time player flow (onboarding)
Repo: https://github.com/IllumaestheticJ/WreckPursuit. git fetch origin; create your branch from origin/lead/round12 (NOT main — it has the newest work). Read CLAUDE.md first (rules: deterministic sim, no wall-clock, SI units, no real car brands, Arcade vs Simulation differ only in damage), then docs/INTEGRATION.md, docs/STATUS.md and docs/art/STYLE_DECISION.md. Stay in the files named below; anything needed elsewhere goes in your doc under "Requests". Gate before pushing: cargo fmt, cargo clippy --workspace -- -D warnings, cargo test (your crates), the wasm build (cd apps/testbed-web && npm run wasm), npx tsc --noEmit, and `just web-e2e` (use CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 to save disk). Commit often with prefixed messages; push your branch. Do NOT open a pull request. When done, write a short summary at the top of your doc (what works, how to try it, known gaps).
Branch: lead/onboarding. Doc: docs/integration/onboarding.md.
Build the first-session flow from docs/design/GDD.md §9 (read it, and docs/design/DEMO_SCRIPT.md, docs/integration/economy.md for the career API): cold open (a short scripted night drive in a borrowed car ending in a crash), the junkyard (pick the junkyard beater from the career's floor car), a first street meet (a short race against 1–2 AI, using the existing race picker / wp_race), first heat (a patrol spots you; escape or get caught, both continue the story), then the garage (repair, first mod). Each step has a one-line objective banner and a skip button; progress saved in the career save (versioned). Use only existing systems (career in wp_wasm::career, races, police); new UI in apps/ui-kit/src/onboarding/ and minimal wiring in apps/testbed-web/src/main.ts. A "New career" in the garage offers "with intro / skip intro". e2e: the whole flow can be completed by a scripted driver with skips allowed; a reload resumes at the same step.
